Overview

Retrieve community events, or use authorized operations to create, replace, and delete event records. The API returns JSON and maintains events in provider-owned storage.

Base URL: Supplied by the API provider during an agreed testing window. This documentation website is not the running API.

Authentication: GET requests are public. POST, PUT, and DELETE require an approved API key sent in the x-api-key header. Never put real credentials in public code or documentation.

GET /api/events

No request body. Returns a JSON array of event objects; an empty array is possible.

GET /api/events/:id

The :id path value is the event's UUID string. Returns the matching event object, or 404 if not found.

POST /api/events

Requires x-api-key and a JSON body with all four event fields. Returns the created event object with a server-generated UUID and HTTP 201.

PUT /api/events/:id

Requires x-api-key, an existing event UUID, and all four event fields. Replaces the event's editable fields while preserving its ID. Returns the updated object with HTTP 200.

DELETE /api/events/:id

Requires x-api-key and an existing event UUID. Returns HTTP 204 with no response body.

Event fields and example

FieldTypeRequirements
idstringServer-generated UUID; included in responses, not required in create/update bodies.
titlestringRequired, nonempty after trimming.
descriptionstringRequired, nonempty after trimming.
datestringRequired date-only YYYY-MM-DD format; must pass server date parsing.
locationstringRequired, nonempty after trimming.

Example request body for POST or PUT (illustrative values; field structure verified against source):

{
  "title": "Online JavaScript Workshop",
  "description": "Functions and practical exercises",
  "date": "2026-11-14",
  "location": "Online"
}

Example successful event object (illustrative identifier and content):

{
  "id": "2b15d442-ec63-4b7d-a071-51a66c70f489",
  "title": "Online JavaScript Workshop",
  "description": "Functions and practical exercises",
  "date": "2026-11-14",
  "location": "Online"
}

For GET collection responses, the event objects are returned inside a JSON array.

Validation, errors, and access

POST and PUT reject missing, non-string, or empty title/description/location values, and dates that fail the format/parsing checks, with HTTP 400:

{ "message": "Valid title, description, date, and location are required." }
StatusWhen it occursResponse
400Invalid POST/PUT bodymessage explaining valid fields are required
401Missing or invalid API key for a protected operation{"message":"A valid API key is required."}
404Unknown event ID for GET/PUT/DELETE by ID{"message":"Event not found."}
500Storage or server failure; or no API credentials configured for protected operationsmessage describing the failed operation or authentication configuration

Protected operations send the credential in the request header:

x-api-key: YOUR_APPROVED_KEY

API-key authentication authorizes a consuming application; it does not establish ownership by an individual user.
